# Codex 定时更新

先有可用工作台与一轮成功更新，再设置。只在用户要求定时更新时发现并使用 Codex 的 automation_update 工具，不写系统 cron、网页定时器或后台接口。

1. 询问缺失的频率、用户时区及运行时刻；已明确的不要重问。默认采用当前线程的 heartbeat，除非用户明确要求每次新任务/独立项目作业。
2. 查找已有同工作台自动化，优先更新，避免重复。使用工具声明要求的完整配置，不直接编造原始自动化指令给用户。
3. 提示词包含下列具体值：Skill 名及可用位置、工作台绝对路径、来源范围、时区。要求按 references/update.md 增量维护，失败窗口重试，沿用分类与稳定 ID，候选校验后备份发布；不覆盖浏览器选择、不扩充历史授权、不发布原文到外部服务。
4. 通知策略：没有新增或可行动变化时保持安静；完成有意义的更新、失败或需要用户处理时通知。不写“每次简短回报”。优先保持已有用户通知偏好。
5. 只有工具返回成功才能说“已设置”。向用户说明本机任务依赖运行环境可用，不保证电脑关机、应用离线时执行；不要把创建计划等同于验证执行。首次执行后再核查记录。

自动化提示词示例（替换具体路径与时区后才提交）：

“使用 $lukk-codex-workbench 维护〈工作台绝对路径〉。按已保存时间范围和各窗口上次成功采集点读取新增或变化内容，并重试历史缺口；沿用用户分类和事情/任务 ID。遵循更新流程，先候选、校验、备份后原子发布。来源不可读时保留现有数据并明确缺口。保持当前视觉和浏览器选择。不自动扩充历史范围。无新增或可行动变化时保持安静；有意义的更新、失败或需要用户处理时通知。时区：〈用户时区〉。”
