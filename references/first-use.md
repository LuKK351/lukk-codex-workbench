# 首次使用

## 先让用户理解要得到什么

简短介绍：本地网页按事情汇总 Codex 讨论，也能按日期回看、搜索原话、打开来源窗口和临时收藏。内容按次更新，不是实时同步，也不替代原来的 Codex 对话。

先检查 Python 3.9+、IANA 时区数据、本机浏览器、可用的 Codex 来源读取工具，以及当前目录是否已有工作台。不要让用户自己安装数据库、提供 API key 或操作 JSON。Windows 优先检测 `py -3`，其次 `python`；macOS/Linux 使用可用的 `python3`。下文命令中的 python3 应替换为已验证解释器。

Windows 通常没有系统 IANA 时区库。先验证 `ZoneInfo` 能读取用户时区；缺少时优先使用独立虚拟环境，执行 `<解释器> -m pip install -r <Skill>/requirements.txt` 安装 tzdata。必须用同一解释器初始化、更新和启动，并把其绝对路径记入 `config/workbench.json` 的 `pythonExecutable`。缺少依赖时明确提示，不将时区默默改为 UTC。文件读写使用 UTF-8；中文、空格路径按当前 shell 正确引用。已存在时继续维护，不重复创建。

## 一次收集必要选择

结合上下文沿用已明确的选项，只询问缺失项：

- **首次时间范围**：近 1 个月（推荐起步）、近 3 个月或自定义起止日期。三个月不是硬上限；半年、一年等较长范围通过自选提供。必须由用户选择，推荐不等于用户已经同意；沿用用户已明确的范围，不因新默认建议而缩减。按用户时区的本轮开始日期计算明确日期，结束日包含当天；近 N 个月按日历月回退，同日不存在取该月末日。
- **保存位置**：给出当前工作区下 `codex-workbench` 的具体绝对路径供采用或改动。不要默认放进 Skill 安装目录。已有目录不覆盖。
- **分类**：展示编程与工具、写作与编辑、设计与制作、学习与研究、规划与决策、整理与事务；可直接沿用或改名、增删，证据不足用未分类。不让用户先设计一套复杂体系。

### 向用户展示的范围说明

首次需要用户选择时，按以下“引导段落＋三列表格＋进度说明”展示，不缩写成“使用频繁”“尽快看到效果”等含糊词语。不谈 token，不根据月份或窗口数量承诺具体分钟数。表格中近一个月、近三个月的选项补上按本轮日期计算的实际起止日期；不照抄历史示例日期。已有明确选择时不重复展示或询问。

**第一次想整理哪些 Codex 对话？**

建议先整理近期内容，看看工作台是否能帮你找回讨论、看清事情进展，之后可以继续补充更早的内容。需要整理的对话越多、内容越长，首次等待通常也越久。

| 整理范围 | 适合的情况 | 建议 |
| --- | --- | --- |
| **近 1 个月（推荐起步）** | 你几乎每天都在 Codex 里讨论或处理事情，已经积累了不少窗口；想先看看这些内容整理成工作台后的效果。 | 先整理近期内容，确认小结、分类和查找方式是否符合需要，再补充更早的讨论。 |
| **近 3 个月** | 你只是偶尔使用 Codex，最近一个月的内容不多；或者需要一起回看过去几个月持续推进的事情。 | 覆盖更长一段时间。如果每天都有大量讨论，这个范围也可能需要较长时间整理。 |
| **自选时间范围** | 你已经知道想找哪个时期的内容，例如半年前讨论过的一个方案。 | 直接选择相关日期，不必为了找旧讨论，把中间所有月份都整理一遍。 |

整理会分批进行，第一批完成后就可以打开网页查看，随后继续处理你选定的范围。具体耗时暂时无法准确预计，过程中会告知已整理多少、还有哪些待处理。

表格后给出建议保存位置和默认分类，集中询问尚未确定的选项；不要让用户回答端口、消息 ID 等技术细节。用户确认范围后，按该范围持续整理。分批执行不代表每批结束都要重新征求同意；只有用户明确选择分阶段缩小范围，才在较小范围完成后结束。若目录显示内容较多，可报告候选数量，但目录不完整时明确“至少发现”，不能据此编造总数或耗时。

说明收藏与接续选择保存在当前浏览器，重启通常保留，清除本站数据会丢失，换地址不会同步。选定并保存稳定的本机端口；如 8770 已被另一个应用使用，选择空闲端口，不停止其他服务。

## 创建与收录

1. 从 Skill 的绝对目录运行 `python3 scripts/initialize.py <新目录> --since YYYY-MM-DD --until YYYY-MM-DD --timezone <IANA时区> [--port 8770]`。参数为已确认范围。创建空白网页、`config/workbench.json` 和未完成状态的 `.workbench/history-collection.json`，没有收录任何用户原文。
2. 按用户修改更新新目录的 `config/default-types.json`。改名保留类型 ID；删除类型前映射已有条目（首次为空）。不要覆盖现有用户分类。
3. 按 [历史收录与完成检查](history-collection.md) 盘点候选窗口，建立持久进度清单。开始批量读取正文前，先检查实际可用的普通目录、归档入口及已授权来源；无法核验完整目录时标明未知，不等全部收录后才寻找其他入口。用更新时间发现候选，用消息日期确定范围；目录只返回近期一部分时，总规模仍未知。正文收录不超出授权范围。
4. 按 [更新流程](update.md) 取得来源、整理、准备与发布首批；collectionCutoff 保存首次读取上界的具体时间与时区，organizedAt 由当前 Skill 的 prepare 自动生成。来源包含边界前上下文时，单独保存为理解背景，不放进本轮时间轴。写明哪些窗口完整到达范围起点、哪些有缺口；不以窗口创建时间筛掉近期仍活跃的老窗口。
5. 按 [打开与维护](maintenance.md) 安装固定入口：macOS 创建桌面应用，Windows 创建桌面快捷方式。使用当前 Skill 的 `desktop.py install`，再用工作台的 `launcher.py` 打开；默认沿用系统浏览器，用户指定常用浏览器时保存其应用路径，不修改系统默认浏览器。只监听本机，不换既定地址。验证服务停止后入口能恢复、重复打开不会多启服务，并检查首屏、事情详情、搜索命中原话、每日回顾和来源入口。Windows 环境必须实际检查生成的快捷方式，不以文件存在代替成功打开。Linux 使用 `launcher.py` 打开并给出稳定地址，暂不调用 desktop.py 安装系统入口。
6. 首批发布与页面检查通过后，以进度消息给出固定入口的位置和可复制的稳定地址，并只在首次打开时简短提醒：“以后点击“打开 Codex 工作台”即可使用，服务停止时会自动恢复。建议在常用浏览器里使用。收藏和‘接着做’的确认、移出选择保存在当前浏览器，换到 Codex 内置浏览器或其他浏览器时不会自动同步。”即使已在 Codex 内置浏览器中展示，也要给出同一 URL；这是建议，不强制切换、不要求用户选择浏览器才能继续，也不替用户更改默认浏览器。Linux 使用同一浏览器存储提醒，但将打开方式改为“可收藏这个地址；服务停止时让 Codex 打开工作台”，不提不存在的桌面入口。随后立即按历史收录清单继续下一批；完成与中断条件统一以 history-collection.md 为准。
7. 历史收录达到可交付的结束条件后，按下方“首次交付的回复格式”交付。固定打开入口放在回复开头；定时更新尚未决定时，必须在末尾明确询问，不能只陈述“未设置定时更新”。首批预览、有可执行历史待办时继续整理，不提前用这个问题结束初始化。

## 首次交付的回复格式

完成检查通过后，按“可用结果 → 下次怎么打开 → 收录结果与边界 → 如何更新 → 定时更新询问”的顺序回复。不是把全部技术验收记录都堆进最终回复；用户需要知道下一次从哪里打开、资料收录到什么时候。

- **固定入口必须突出**：放在开头两段内、统计与试用建议之前，用独立的加粗一行展示实际位置和入口名称，不埋在列表、长段落或边界说明之后。可用实际绝对路径做可点击链接，另给已验证的网页地址；不只显示一个容易与桌面入口混淆的网页链接。
- 入口名称、位置以 `desktop.py install/status` 返回结果为准，保留实际生成的后缀。位于自选目录时写该目录，不一律说“桌面”；只有创建和启动验证均成功，才说入口已可用及能恢复服务。Linux 或入口安装失败时改为显眼的实际打开方式，不虚构快捷方式。
- 收录数量、范围、读取截止时间和具体缺口仍要保留；一次目录上限不等于全账号窗口总数。使用引导最多列 2—3 条。常用浏览器提醒保留一句，不重复多段说明。
- **结尾必须给出可以回答的问题**：初始化结束且用户尚未决定资料定时更新时，询问是否现在创建，可举“每天早上 8 点，按用户时区”为例，同时允许其他频率或暂不设置。例子只是建议，不代表已授权；用户选择后按 scheduling.md 执行。可用当前环境的提问工具或直接在最终回复中提问，不能止于“可以设置”“本次没有设置”。不必为等待可选回答持续占用当前回合。
- 已明确拒绝或选择稍后设置，不重问；已有同一工作台的有效计划，说明实际安排，不邀请重复创建；已授权且频率、时间、时区明确，先核对已有计划并执行，再报告实际结果。用户已授权但信息不全，只问缺失项。自动化工具不可用时明确限制，不问一个当前无法兑现的“现在创建”问题，也不把失败说成成功。
- 登录后启动阅读服务和资料定时更新分开说明。前者仅适用于 macOS/Windows，不弹浏览器、不整理资料；未选不启用。可简短提及当前登录启动状态和可选用途，不把两个开关合并成一个“自动更新”，也不因用户同意其中一项代选另一项。

以下为结构示例，尖括号全部替换为已核验的实际值；根据平台、入口结果、用户既有选择调整，不机械照抄：

工作台已建好，可以开始使用：[现在打开工作台](〈已验证的本地 URL〉)。

**下次打开：双击〈实际位置，如桌面〉「〈实际入口名称〉」。**

〈入口恢复验证通过时：服务停止时，这个入口也会自动恢复并打开网页。〉建议固定在常用浏览器使用，收藏和接续选择不会跨浏览器同步。

**本次整理**：〈实际范围、对话数、事情数〉；读取截止到〈年月日、时分、用户时区〉。〈如有目录边界或正文缺口，在这里简明说明，不宣称全量。〉

可以先搜索一件记得的事，核对小结和原话；也可以在“可以接着做”中查看待确认事项。以后手动更新，在 Codex 里说“更新对话整理工作台”即可。

〈macOS/Windows 且已核验时：登录后自动启动阅读服务目前〈实际状态〉，它与资料定时更新是两个独立选项。〉

**要现在设置定时更新吗？** 比如每天早上 8 点（〈用户时区的易读名称〉）整理新增讨论；你也可以指定其他频率和时间，或者暂不设置、需要时手动更新。

## 首次失败与中断

- 无法读取原文：保留已建模板，说明缺少哪个来源能力；请求用户提供授权导出或明确本地来源，不冒充自动初始化完成。
- 部分失败：已校验成功的批次可保留，未读窗口进入批次缺口清单，下次优先补读。成功窗口和失败窗口分别记进度，不以统一“今天”跳过失败内容。
- 中断后：检查最近候选报告和正式数据哈希。未发布候选经校验仍可发布；正式数据已变则重新基于它生成候选。不要重复创建事情。
- 初次选的时间是回溯范围，不是保留期限；更新不会把三个月以前的已收录内容删掉。

## Windows 使用示例与验收

PowerShell 中，若已验证 `py -3` 的 Python 与时区依赖可用，可执行以下命令；实际由 Codex 代用户完成，路径改为选定位置：

```powershell
py -3 "$env:USERPROFILE\.codex\skills\lukk-codex-workbench\scripts\initialize.py" "$env:USERPROFILE\Codex 工作台" --since 2026-07-28 --until 2026-10-28 --timezone Asia/Shanghai
py -3 "$env:USERPROFILE\.codex\skills\lukk-codex-workbench\scripts\desktop.py" install "$env:USERPROFILE\Codex 工作台"
py -3 "$env:USERPROFILE\Codex 工作台\scripts\launcher.py" "$env:USERPROFILE\Codex 工作台"
```

日期仅为命令示例，执行时必须换成用户选择。若使用虚拟环境，PowerShell 调用带空格的解释器路径需 `& "<venv>\Scripts\python.exe"`。安装目录优先 `$CODEX_HOME/skills`，未设置时使用用户主目录 `.codex/skills`。不把 macOS 的 `/Users/...` 路径复制给 Windows 用户。

维护者可运行 `<解释器> <Skill>/scripts/self_test.py`：在临时目录验证中文路径、首次初始化、发布、重复执行、回退、跨进程锁、进程退出释放锁及本机服务，结束自动清理。脚本不会读取个人对话。已通过 macOS 本机及 macOS/Windows/Linux CI 隔离测试，Windows 包含真实快捷方式调用及登录入口创建/撤销；不等同于用户机器安装、整机重启或所有系统策略验收。实际安装时仍核对用户入口。
