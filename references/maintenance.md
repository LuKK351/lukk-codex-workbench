# 打开已有工作台与升级

## 换对话、重启后找回

先用当前对话中已知路径和当前工作区的 `config/workbench.json` 定位。当前目录没有工作台不等于用户没建过：用户要求打开或更新时，查可用 Codex 对话目录中的安装/初始化记录，或请用户提供原地址/路径；不扫描整个磁盘，也不另建一个空工作台。多个候选时让用户选定。

读取配置中的解释器、时区、端口和 URL，检查解释器仍存在且依赖可用。已失效时检测替代解释器并验证相同依赖，再更新配置，不能直接使用机器上任意 Python。

先检查保存的 URL 是否已有服务，并核对其 data.json 与目标目录内容是否相符；相符则直接打开，不重复启动。已升级固定入口时，用配置中的解释器执行工作台的 `scripts/launcher.py <工作台>`；它检查服务身份、恢复后台运行，再打开浏览器。用 `--ensure-only` 只恢复服务，`--status` 只检查。旧工作台先按下方“升级已有工作台”安装入口。用实际 HTTP 请求确认响应后再说已打开。不能只根据启动命令已提交或预览链接生成就宣称服务可用。

如果用户在另一浏览器里看不到收藏，先解释浏览器保存范围，建议回原浏览器和原地址查看；不要误判为工作台数据丢失而重建。

已有工作台的端口被其他服务占用时，不停掉他人服务，也不静默换端口：说明换地址会隔离原浏览器收藏和接续选择，再让用户决定是否换地址。新建空工作台则可直接选择空闲端口。localhost 与 127.0.0.1 也属于不同站点，沿用配置 URL。

## 更新 Skill 与更新网页分开处理

更新 Skill 说明不会自动替换已有工作台的网页和 scripts 目录。先查看更新范围：

- 只有流程说明变化：更新安装目录中的相应说明，让当前执行重新读取；不重新初始化，不复制空模板覆盖工作台。
- 需要同步程序或网页：比较文件与用户已有修改，先备份待替换文件，再同步明确需要更新的 app.js、core.js、style.css、index.html 或 scripts 文件。保留 data.json、config、.workbench 和浏览器选择，解释器与 URL 沿用原配置。自定义改动冲突先展示差异，不直接覆盖。
- 涉及数据格式变化：先准备可检查的迁移与回退方案，不能靠替换空模板完成升级。没有迁移方案时保留原可用版本。

同步后检查现有数据能校验、网页能打开，抽查已有事项与来源。安装器提示目标 Skill 已存在时，应更新现有安装，不让用户为了升级删除工作台或重新收录。

## 固定打开入口与可选登录自启动

以下命令由 Codex 执行，不让普通用户管理终端。`<Python>` 为配置中验证过的绝对解释器路径，`<Skill>` 和 `<工作台>` 都用绝对路径并按 shell 正确引用。

```text
<Python> <Skill>/scripts/desktop.py install <工作台>
<Python> <工作台>/scripts/launcher.py <工作台>
<Python> <工作台>/scripts/launcher.py <工作台> --ensure-only
<Python> <工作台>/scripts/launcher.py <工作台> --status
<Python> <Skill>/scripts/desktop.py status <工作台>
```

- macOS 默认生成桌面“打开 Codex 工作台.app”；Windows 通过系统接口取得真实桌面路径（含 OneDrive 重定向），生成 `.lnk`。都不要求管理员权限。多个工作台遇到同名入口时加唯一后缀，不覆盖其他入口。
- `install --entry-dir <目录>` 可指定入口位置；默认用系统浏览器。用户明确指定其他常用浏览器时，用 `--browser <应用绝对路径>` 保存选择（macOS `.app`，Windows 浏览器 `.exe`）；`--browser default` 才恢复跟随系统默认。浏览器失效时说明，不偷偷换浏览器。不同浏览器用户配置的收藏也不互通。
- launcher 复用健康检查身份匹配的服务；停止时后台启动，轮询确认成功再打开。与数据发布使用不同的锁，重复打开不会多启服务。日志在 `.workbench/service.log`，错误诊断在 `.workbench/launcher-error.txt`，不收录聊天原文。
- 用户说“打不开”时先读诊断和配置，不要求重装或删除数据。入口记录在 `.workbench/desktop.json`。解释器或浏览器修复后重新 `install`，同时刷新已启用的登录入口，保留其开关；不自动迁移工作台目录。

用户明确选择登录后自动启动时才执行：

```text
<Python> <Skill>/scripts/desktop.py enable-login <工作台>
<Python> <Skill>/scripts/desktop.py disable-login <工作台>
```

macOS 使用当前用户的 LaunchAgent，Windows 使用当前用户 Startup 文件夹快捷方式。启用时先验证运行环境和服务可启动；登录触发在下次登录生效，不会弹浏览器，也不读取或整理对话。不需要后台更新权限或网络服务。不要把“已配置”说成“已验证整机重启”。Windows 系统启动项或 macOS 登录项若被用户/系统禁用，需要核对系统状态；本地 manifest 只证明安装记录，不能证明系统仍允许启动。关闭自启动只撤销下次登录启动，当前网页继续可用；固定入口照常使用。

解释给用户：

> 以后点击“打开 Codex 工作台”即可使用。若开启登录后自动启动，也可以从浏览器书签直接打开。资料由 Codex 按你设置的时间更新。

### 升级已有工作台

先保留原 URL、端口、浏览器选择和所有数据。将当前 Skill 的 `scripts/launcher.py`、`scripts/serve.py` 与工作台运行脚本比较；备份需替换文件，存在用户改动则核对差异后再同步。不要复制空模板覆盖数据。`desktop.py install` 会为旧配置补上唯一身份并保留其他配置；初始化器已为新工作台生成身份。

若原地址有旧版服务但没有健康检查接口，launcher 会报告占用。先核对其 data.json 与目标目录一致，再检查实际进程命令确实指向该工作台的旧 serve.py，才能停止该已确认进程并用新 launcher 恢复。不能根据端口或过期 PID 文件盲目杀进程。若无法核实，保留服务、说明阻碍，不静默换端口。

验收优先用隔离工作台运行 `scripts/launcher_test.py`；macOS 可额外运行 `scripts/desktop_native_test.py`，用临时应用和临时 launchd 任务验证真实系统调用，结束清理。再实际打开用户入口确认同一地址；若需停服务来验证恢复，只停自己启动或已核实属于目标的进程，不影响其他工作台。已有浏览器收藏和任务选择不动。

### 移除入口或卸载

```text
<Python> <Skill>/scripts/desktop.py uninstall <工作台>
```

此命令先撤销登录入口，再移除本工具创建且未被改动的桌面入口，重复执行无副作用；保留工作台数据、浏览器选择及当前阅读服务。真正删除工作台或卸载 Skill 前先做这一步，避免残留失效入口。用户另外要求停止服务/删除数据时，分别核实目标并按授权执行，不能把移除入口等同于删除历史。入口被用户改动时保留并报告，不强制删除。
