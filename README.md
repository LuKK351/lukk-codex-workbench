# Codex 对话整理工作台

把散落在 Codex 窗口里的讨论，整理成一个可以搜索、按事情浏览、按日期回看的本地网页。

记得聊过一个方案，却忘了在哪个窗口？一件事情分散在几个对话里？回来后想看看哪些内容可能还要继续？这个 Skill 用已收录的讨论帮你找回线索，保留原话与来源入口。

**调用名：`lukk-codex-workbench` · 界面名称：Codex 对话整理工作台**

## 能做什么

- **事情总览**：同一目标跨窗口汇总，同一窗口中的不同事情分别整理。
- **每日回顾**：按日期看当天讨论与变化，区分当天来源和事情的全部来源。
- **搜索与定位**：支持关键词、整句描述、有限近义说法与错字容错；从结果定位到收录原文。
- **可以接着做**：整理可能继续的事情，区分明确接续和进展待确认；可以确认、移出和恢复。
- **临时收藏**：保存在当前浏览器，便于稍后回看。
- **初始化与更新**：由 Codex 引导选择首次时间范围，分批整理；支持手动更新，并可按需设置 Codex 定时更新。

网页是本地阅读工具。整理工作由 Codex 与 Skill 完成，不需要为网页配置模型 API key、数据库或业务后台。

## 安装：把链接交给 Codex

在 Codex 中打开一个新对话，发送：

> 请从 https://github.com/LuKK351/lukk-codex-workbench 安装这个 Skill。安装后按它的首次使用流程引导我建立工作台，先问我收录时间范围、保存位置和分类，不要直接整理全部历史。

仓库根目录就是 Skill 目录，包含 `SKILL.md`、`references/`、`scripts/` 和空白网页模板。安装时应保留完整目录结构，目录名使用 `lukk-codex-workbench`。

默认安装到 `~/.codex/skills/lukk-codex-workbench`；如果设置了 `CODEX_HOME`，则使用其 `skills` 子目录。Windows 对应用户目录下的 `.codex\skills\lukk-codex-workbench`。已有同名安装时先检查，不能直接覆盖用户工作台。

如果安装后 Skill 列表尚未刷新，重新打开 Codex 或开启新对话，再发送：

> 使用 $lukk-codex-workbench，帮我初始化一个对话整理工作台。

## 第一次会经历什么

1. **检查环境与来源能力**：确认 Python、时区数据，以及当前 Codex 环境能读取哪些对话正文。
2. **选择首次范围**：近 3 个月、半年、一年或自定义日期；不会默认读取全部历史。
3. **确认位置与分类**：工作台单独保存，不放在 Skill 安装目录。默认六类可直接用，也可修改。
4. **创建空白工作台，分批整理**：先验证首批，再继续完成授权范围；读取失败或正文不全会明确列出。
5. **打开网页验收**：检查事情、原话、搜索、每日回顾与来源入口。
6. **按需设置定时更新**：首次整理完成后再决定频率与时刻，不默认启用。

默认分类按事情的主要目标划分：编程与工具、写作与编辑、设计与制作、学习与研究、规划与决策、整理与事务。无法确定时保留未分类，不要求你先给全部窗口打标签。

**首次时间范围不等于保留期限。** 后续更新不会自动删除超出该范围的旧记录。

## 日常使用

打开工作台后，在网页里搜索和回看。需要更新时，在 Codex 中说：

> 使用 $lukk-codex-workbench 更新我的工作台，只补充上次成功整理后的变化。

需要补历史或定时时，可以说：

> 把首次范围以外的某个月补进工作台。
>
> 帮我设置每天晚上 9 点更新，使用我的本地时区。

多份工作台同时存在时，请指定目标路径。更新沿用已保存的分类和稳定 ID，先生成候选并校验，再备份、替换正式数据；失败时保留旧数据，支持回退。

网页服务停止后，地址会暂时打不开。可让 Codex 按工作台配置重新启动；本版不包含开机自启或永久后台常驻。

## 环境与兼容性

| 项目 | 要求或当前状态 |
| --- | --- |
| Codex | 能使用本地 Skill、读写本地文件；正文读取及自动化能力取决于当前运行环境 |
| Python | 3.9 或以上 |
| 浏览器 | 现代桌面浏览器；分词能力较弱的浏览器使用有限回退 |
| macOS | 已做原生端到端自检 |
| Windows | 已适配文件锁、UTF-8、PowerShell 路径及启动方式；API 分支已模拟验证，尚未做原生实机验收 |
| Linux | 使用 POSIX 文件锁；尚未在本轮做原生实机验收 |
| 时区数据 | 使用 IANA 时区；缺失时安装随包声明的 `tzdata`，Windows 通常需要 |

Codex 会协助检查依赖。维护者可在 Skill 目录执行隔离自检：

```sh
# macOS / Linux
python3 scripts/self_test.py
```

```powershell
# Windows
py -3 scripts/self_test.py
```

缺少时区数据时，应在同一 Python 环境安装 `requirements.txt` 中的依赖。自检只使用临时模拟数据，不读取个人聊天。

## 数据放在哪里

- **安装目录**：Skill 说明、脚本与空白模板，不保存你的工作台内容。
- **你选定的工作台目录**：已收录正文、整理结果、配置、批次记录与数据备份。
- **当前浏览器**：收藏、接续确认与移出选择。普通刷新和重启通常保留；清除本站数据会丢失，换浏览器或地址不会自动同步。

本地服务只监听 `127.0.0.1`，只开放网页需要的资源。不要把使用中的工作台目录公开上传；分享本仓库即可。工作台数据备份不包含浏览器收藏。

网页搜索不调用远程模型。整理过程由你的 Codex 环境处理原文，因此**不代表 AI 整理完全离线**；Skill 不额外把原文发给其他 AI 或第三方整理服务。

## 使用边界

- 收录的是当前环境可访问且你授权的内容，不承诺自动拿到全账号历史。
- 窗口目录、摘要和截断内容不能冒充完整原文。无可用正文时会停在空模板，说明缺口，再使用你授权的导出或本地来源。
- 当前不收录 ChatGPT 对话、附件正文与工具执行日志。
- 搜索是本地词语线索与有限容错，不是任意语义都能理解；未收录内容无法被搜索出来。
- 接续状态根据已收录讨论判断，可能不知道其他窗口或线下进展，所以提供本地修正入口。
- 定时更新需要当前 Codex 环境支持自动化，且相关运行环境可用；电脑关机或应用离线时不保证执行。

```text
SKILL.md                 Skill 入口
agents/openai.yaml       显示名称与调用提示
references/              首次使用、整理标准、数据契约、更新与定时流程
scripts/                 初始化、发布校验与隔离自检
assets/template/         不含个人记录的绿色网页模板
requirements.txt         时区数据依赖
```
